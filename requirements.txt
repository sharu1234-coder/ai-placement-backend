# History worth knowing before touching the pins below: this file used to be resolved on a
# local Python 3.9.0 checkout, and that single fact -- not neglect -- is what held ~10
# packages at versions with known CVEs. Every current fix release for them requires Python
# >=3.10 (cryptography's marker even excludes 3.9.0 specifically), so on 3.9 there was
# genuinely nothing to bump to, and earlier comments here recorded that as "no fix published
# yet" -- which read as "unfixable by anyone" when the truth was "unfixable on this machine".
# CI and production were already on 3.12 but inherited these exact pins, so they shipped
# artificially old packages for no reason at all. Keep local, CI and production on the same
# interpreter; if you find yourself unable to install a fix release, check your Python
# version before concluding the fix does not exist.

# Production cloud AI provider (AI_PROVIDER=anthropic). Held at 0.x deliberately; there is an
# open Dependabot PR for 1.3.0. Python 3.12 removed the constraint that previously forced 0.x,
# and the API surface this project actually uses was checked against a real 1.3.0 install --
# anthropic.Anthropic(api_key=, timeout=), client.messages.create, client.messages.parse,
# APIConnectionError / APIStatusError / AnthropicError, and parse's output_format= keyword all
# still exist. On surface alone it looks drop-in.
#
# It is still not bumped, for a reason specific to this app rather than to the SDK: every AI
# failure here degrades SILENTLY. AIGenerationError is caught at each call site and falls back
# to hand-authored template text, returning 200 the whole way (the same class of problem the
# ollama-on-loopback startup check exists to catch). And tests/unit/test_anthropic_provider.py
# mocks the client, so the suite exercises this provider's error handling but never a real
# response shape. A subtle 1.x change in what messages.parse returns would therefore leave
# both the tests green and production quietly serving generic text.
#
# Bump it when someone can run a live smoke test with a real ANTHROPIC_API_KEY against a
# staging deployment and confirm a genuine structured generation still parses -- not before.
# Also worth doing then: parse's output_format= is superseded by output_config=, so migrate
# that in the same pass rather than leaving a deprecated request shape behind.
anthropic==0.125.0
